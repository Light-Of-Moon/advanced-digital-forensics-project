# The Digital Forensics Evidence Pipeline (Digital_V3)

## The Story: Securing the Digital Crime Scene

Imagine a crime scene, but not one cordoned off with physical yellow tape. This is a digital crime scene. Investigators seize devices and extract thousands of files—images, videos, documents, and system logs. The most critical challenge in modern investigations isn't just finding the data; it's proving that a piece of digital evidence presented in a court of law is exactly what was extracted, completely unaltered, and accompanied by a crystal-clear chain of custody. 

Enter the **Digital Forensics Evidence Pipeline (Digital_V3)**. This system acts as an impenetrable vault and an all-seeing eye for digital forensics. It takes raw, chaotic data and transforms it into unassailable, court-ready evidence. When an investigator uploads a file, the system immediately begins interrogating the data—pulling deep binary metadata, spotting signs of manipulation, and permanently anchoring the file's unique fingerprint into a blockchain ledger. No tampering goes unnoticed; no transfer goes unlogged. 

## The Purpose of the System

The primary purpose of this system is to provide a **forensic-grade digital evidence management platform**. It is designed to:
1. **Ensure Immutability:** By computing SHA-256 and MD5 hashes and registering them on a blockchain, it guarantees that evidence cannot be tampered with or secretly altered.
2. **Uncover the Unseen:** Perform deep binary-level extraction (including C2PA/JUMBF manifests, EXIF data, GPS coordinates, and raw file headers) to determine the origin of a file and whether it has been edited by software like Photoshop or AI generators.
3. **Maintain Chain of Custody:** Track every single interaction with the evidence—from the moment of upload, through transfers between analysts, to final verification—ensuring strict audit transparency.
4. **Enforce Security:** Implement rigorous role-based access control (RBAC), ensuring that only authorized personnel (Admins, Investigators, Analysts) can interact with specific cases and evidence.

## Full System Design

The architecture of Digital_V3 is a monolithic, highly cohesive application divided into distinct layers:

### 1. Presentation Layer (Frontend)
A responsive Single Page Application (SPA) built using vanilla HTML, CSS, and JavaScript. It provides a professional, icon-based user interface tailored for law enforcement and forensic analysts. It communicates asynchronously with the backend API to handle evidence uploads, case management, and real-time chain of custody visualization.

### 2. Application & API Layer (Backend)
Built with Python and **Flask**, this layer exposes RESTful APIs to the frontend. It orchestrates authentication (via JWT), handles file uploads, routes requests, and enforces role-based access control (RBAC) and rate-limiting. 

### 3. The Forensic Engine
A specialized module (`metadata_extractor.py`) that acts as the core investigative tool. It rips apart files at the binary level to extract hidden metadata. It supports images, PDFs, videos, and archives, scanning for software signatures and editing indicators (e.g., detecting if a photo was shared via WhatsApp or generated by DALL-E).

### 4. The Immutable Ledger (Blockchain)
A custom-built Python blockchain (`blockchain.py`) that operates alongside the traditional database. Every time evidence is uploaded, analyzed, or transferred, a new block is mined containing the action, the user ID, and the file's hash. This provides an append-only, tamper-proof history.

### 5. Data Persistence Layer
Powered by **SQLAlchemy** (using an SQLite database), this layer stores the relational data. It maintains tables for Users, Cases, Evidence, Custody Logs, Analyst Notes, and exhaustive Audit Logs.

## Project Structure & File Index

Here is the complete breakdown of every file in the project and its exact role within the system:

### Backend Files
* **`./backend/app.py`**
  * **Purpose:** The central nervous system of the application. It initializes the Flask server, defines all RESTful API endpoints, handles file uploads, connects the frontend to the database, and enforces authentication and rate-limiting.
* **`./backend/auth.py`**
  * **Purpose:** The security gatekeeper. It handles password hashing, JWT token creation and verification, and provides decorators for role-based access control (e.g., `@admin_required`, `@investigator_required`).
* **`./backend/blockchain.py`**
  * **Purpose:** The truth anchor. A custom Python blockchain implementation that ensures evidence immutability. It creates blocks for evidence registration and custody transfers, validating the entire chain to prevent data tampering.
* **`./backend/metadata_extractor.py`**
  * **Purpose:** The forensic microscope. A massive utility script that interrogates uploaded files. It computes file hashes, extracts EXIF/GPS data, detects MIME types, reads binary headers, finds C2PA/JUMBF manifests, and mathematically scores whether a file has been artificially edited.
* **`./backend/database.py`**
  * **Purpose:** The database connection manager. It sets up the SQLAlchemy database engine and session factory, ensuring smooth transactions between the Python code and the SQLite database.
* **`./backend/models.py`**
  * **Purpose:** The data blueprints. Defines the SQLAlchemy ORM models (schemas) for all system entities: `User`, `Case`, `CaseAssignment`, `Evidence`, `CustodyLog`, `AuditLog`, `AnalystNote`, and `VerificationLog`.
* **`./backend/certificate.py`**
  * **Purpose:** The official stamp. Likely responsible for generating cryptographic verification certificates or printable PDF reports that prove an evidence file's authenticity and chain of custody for court use.
* **`./backend/config.py`**
  * **Purpose:** The environment blueprint. Stores configuration variables, secret keys, upload folder paths, and allowed file extensions to keep the app secure and modular.

### Frontend Files
* **`./frontend/index.html`**
  * **Purpose:** The structural skeleton of the application. A single-page HTML layout that loads the UI dashboard, login screens, and evidence management views.
* **`./frontend/style.css`**
  * **Purpose:** The aesthetic engine. Contains all the CSS styling, modern animations, and layout grids to ensure a professional, forensic-grade, and intuitive user interface.
* **`./frontend/app.js`**
  * **Purpose:** The interactive brain of the client. Handles DOM manipulation, intercepts form submissions, manages the user session, and makes asynchronous fetch requests to the backend API.

### Root / System Files
* **`./run.py`**
  * **Purpose:** The ignition switch. A simple Python script used to bootstrap and launch the Flask development server.
* **`./requirements.txt`**
  * **Purpose:** The dependency manifest. Lists all Python libraries (like Flask, SQLAlchemy, Pillow, Bleach) required to run the backend environment.
* **`./forensics.db`**
  * **Purpose:** The active memory. The compiled SQLite database file that persistently stores all the application's runtime data (users, cases, logs).
* **`./test_jwt.py`**
  * **Purpose:** The diagnostic tool. A small test script to quickly verify that JSON Web Token generation and decoding logic is functioning correctly.
