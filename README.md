## The Story: Securing the Digital Crime Scene

Imagine a crime scene, but not one cordoned off with physical yellow tape. This is a digital crime scene. Investigators seize devices and extract thousands of files—images, videos, documents, and system logs. The most critical challenge in modern investigations isn't just finding the data; it's proving that a piece of digital evidence presented in a court of law is exactly what was extracted, completely unaltered, and accompanied by a crystal-clear chain of custody.

Enter the **Digital Forensics Evidence Pipeline (Digital_V3)**. This system acts as an impenetrable vault and an all-seeing eye for digital forensics. It takes raw, chaotic data and transforms it into unassailable, court-ready evidence. When an investigator uploads a file, the system immediately begins interrogating the data—pulling deep binary metadata, spotting signs of manipulation, and permanently anchoring the file's unique fingerprint into a custom blockchain ledger. No tampering goes unnoticed; no transfer goes unlogged.

---

## Key Features & System Purpose

The primary purpose of this system is to provide a **forensic-grade digital evidence management platform**. It is designed to:

1. **Ensure Immutability:** By computing SHA-256 and MD5 hashes and registering them on a custom-built Python blockchain ledger, it guarantees that evidence cannot be tampered with or secretly altered.
2. **Uncover the Unseen:** Perform deep binary-level extraction (including C2PA/JUMBF manifests, EXIF data, GPS coordinates, and raw file headers) to determine the origin of a file and whether it has been edited by software like Photoshop or AI generators.
3. **Maintain Chain of Custody:** Track every single interaction with the evidence—from the moment of upload, through transfers between analysts, to final verification—ensuring strict audit transparency.
4. **Enforce Security:** Implement rigorous role-based access control (RBAC), ensuring that only authorized personnel (Admins, Investigators, Analysts) can interact with specific cases and evidence.

## Architecture Design

The architecture of Digital_V3 is a highly cohesive application divided into distinct layers:

### 1. Presentation Layer (Frontend)
A responsive Single Page Application (SPA) built using vanilla HTML, CSS, and JavaScript. It provides a professional, icon-based user interface tailored for law enforcement and forensic analysts. It communicates asynchronously with the backend API to handle evidence uploads, case management, and real-time chain of custody visualization.

### 2. Application & API Layer (Backend)
Built with Python and **Flask**, this layer exposes RESTful APIs to the frontend. It orchestrates authentication (via JWT), handles file uploads, routes requests, and enforces role-based access control (RBAC) and rate-limiting.

### 3. The Forensic Engine (`metadata_extractor.py`)
A specialized module that acts as the core investigative tool. It rips apart files at the binary level to extract hidden metadata. It supports images, PDFs, videos, and archives, scanning for software signatures and editing indicators (e.g., detecting if a photo was shared via WhatsApp or generated by DALL-E).

### 4. The Immutable Ledger (`blockchain.py`)
A custom-built Python blockchain that operates alongside the traditional database. Every time evidence is uploaded, analyzed, or transferred, a new block is mined containing the action, the user ID, and the file's hash. This provides an append-only, tamper-proof history.

### 5. Data Persistence Layer
Powered by **SQLAlchemy** (using an SQLite database), this layer stores the relational data. It maintains tables for Users, Cases, Evidence, Custody Logs, Analyst Notes, and exhaustive Audit Logs.

## 📂 Project Structure & File Index

### ⚙️ Backend Files
* **`backend/app.py`**: The central nervous system. Initializes the Flask server, defines RESTful API endpoints, and handles core application logic.
* **`backend/auth.py`**: The security gatekeeper handling password hashing, JWT creation, and `@role_required` decorators.
* **`backend/blockchain.py`**: The custom Python blockchain implementation that ensures evidence immutability and validates the entire chain.
* **`backend/metadata_extractor.py`**: The forensic microscope that interrogates files at the binary level for deep metadata and signs of tampering.
* **`backend/database.py`**: Database connection manager setting up the SQLAlchemy engine.
* **`backend/models.py`**: The ORM blueprints defining models for `User`, `Case`, `Evidence`, `CustodyLog`, and `AuditLog`.
* **`backend/certificate.py`**: Generates cryptographic verification certificates or printable PDF reports.
* **`backend/config.py`**: Stores environment variables, secret keys, upload folder paths, and file size limits (Max 100MB).

### Frontend Files
* **`frontend/index.html`**: The structural skeleton of the SPA.
* **`frontend/style.css`**: The aesthetic engine providing a professional, forensic-grade, and intuitive UI.
* **`frontend/app.js`**: Handles DOM manipulation, authentication state, and makes asynchronous fetch requests.

### System Files
* **`run.py`**: The application entry point. Bootstraps and launches the Flask server.
* **`requirements.txt`**: Dependency manifest for the Python environment.
* **`forensics.db`**: The SQLite database file storing persistent runtime data.

## Getting Started

### Prerequisites
* Python 3.10+
* Virtual Environment (recommended)

### Installation

1. **Clone the repository (or navigate to the project folder):**
   ```bash
   cd Digital_V3
   ```

2. **Create and activate a virtual environment:**
   ```bash
   python3 -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. **Install the dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Run the Application:**
   ```bash
   python run.py
   ```
   The application will start the development server. 
   Access the frontend at: `http://localhost:5000`

## Security & Auditing

The system enforces rate limiting (e.g., 200 requests per day, 10 logins per minute) and uses secure HTTP headers via CORS configuration. Every action, including failed login attempts and file views, is permanently registered to the audit log or the blockchain ledger.
